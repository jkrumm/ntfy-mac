# Release process

The root `AGENTS.md` keeps the rule: the release is the manual Release workflow, never a tag or a publish by hand. The steps, the repository secrets and recovery are here.

1. `make check` gates the run.
2. semantic-release (`.releaserc.json`, no package.json) picks the version from the commits. The exec plugin runs `scripts/stamp-version.sh <version>` and `make package VERSION=<version>`; the dev tree keeps `2.0.0-dev` and the stamp is never committed.
   The run needs these repository secrets, checked before anything is tagged: `APPLE_TEAM_ID`, `APPLE_DEVELOPER_ID_P12_BASE64` (Developer ID Application certificate with its private key, exported from the mini's signing keychain), `APPLE_DEVELOPER_ID_P12_PASSWORD`, `APPLE_DEVELOPER_ID_PROFILE_BASE64` (the Developer ID provisioning profile, base64), `ASC_KEY_P8`, `ASC_KEY_ID`, `ASC_ISSUER_ID` (the App Store Connect Team key), `SPARKLE_ED_PRIVATE_KEY` (content of the key file; `~/.local/state/apple-developer/sparkle-ntfy-mac-ed25519.key`). Set each with `printf '%s' "$value" | gh secret set <NAME>`: a trailing newline stays in the secret. The `.p12` is built with `openssl pkcs12 -export` from `developer-id.key` and `developer-id.cer.pem` in `~/.local/state/apple-developer/`, because `security export` waits on a GUI dialog on the headless mini. The build signs with Developer ID, notarizes and staples (`SIGN_IDENTITY=developer-id NOTARIZE=1`, `NOTARY_TIMEOUT=90m`; a first submission can queue for hours).
3. The GitHub plugin creates a draft, uploads `ntfy-mac-<version>-arm64.tar.gz`, `NtfyMac-<version>.zip`, `appcast.xml` and `SHA256SUMS`, then publishes, so assets exist before the release is visible. The git plugin commits `CHANGELOG.md` (`chore(release): <version>`); semantic-release owns that file.
4. The `tap` job renders `packaging/ntfy-mac.cask.rb.in` into `Casks/ntfy-mac.rb` in `jkrumm/homebrew-tap`, removes `Formula/ntfy-mac.rb`, keeps `"ntfy-mac": "jkrumm/tap"` in `tap_migrations.json` (other entries stay), runs `brew style` and `brew audit --cask --online --strict` and pushes. The cask has `auto_updates true` (Sparkle updates the app; a bare `brew upgrade` on Homebrew 7.0.13 still upgrades a copy older than the tap and skips one already at the tap's version), the `app` and `binary` stanzas, and a `preflight_steps` that removes the `~/Applications/NtfyMac.app` link the formula caveats suggested (a link only, never a real folder). The migration: `brew update` unlinks an installed formula and runs `brew install --cask` when the tap is trusted (brew 7 trust); the old keg stays until `brew uninstall --formula ntfy-mac`. Brew 7 DSL: `depends_on macos: :sequoia` and `preflight_steps` (the string comparison and the Ruby `preflight` are deprecated).
5. The tarball root is `NtfyMac.app/` plus `LICENSE`; the sibling file keeps Homebrew from stripping the lone `.app`.

Release recovery: semantic-release tags first. If the GitHub release or the asset upload fails after the tag exists, re-running the workflow will not publish. Delete the tag and the draft release, then re-run the workflow. If the release exists but the `tap` job did not run, render the cask with `scripts/render-cask.sh <version> <sha256-of-the-zip>` into `Casks/ntfy-mac.rb`, `git rm Formula/ntfy-mac.rb`, keep `tap_migrations.json` and push it to `jkrumm/homebrew-tap` by hand.

2.0.0 was published on 2026-11-13 (first run, no recovery needed). From here the commits since the last tag decide the version.
