# ntfy-mac 2.0 — native Swift rewrite

**Goal:** one native Swift app replaces the Bun daemon and the Swift helper. It has a menu bar extra, a message history window and native settings. A CLI-first `ntfy-mac` drives the same core: every setting and action works from the CLI, and the UI is a convenience over it. Existing 1.x users upgrade without re-configuring. The direct build (Homebrew + curl) ships first, and a Mac App Store build follows once the Apple Developer membership is active.

**Gate:** `make check`. Wave 1 creates it: `swift build`, `swift test`, the swift-format lint, `xcodebuild` of the app scheme, and `bun run validate` while `src/` still exists. Then `/review` on the wave diff.

## Ground rules (every wave)

- **Compatibility contract.** 2.0 must keep everything below working, or migrate it on first run:
  - Config file `~/.config/ntfy-mac/config.json` (`url`, `token`, `sounds`, `dismiss`, `extraTopics`).
  - Environment variables `NTFY_URL`, `NTFY_TOKEN`, `NTFY_TOPICS`, `NTFY_DEBUG`.
  - State file `~/.local/share/ntfy-mac/state.json`, so the `lastMessageId` cursor carries over.
  - Every 1.x command and flag: `setup [--url --token]`, `doctor [--json]`, `subscribe [topic|reset]`, `unsubscribe`, `config [sounds|dismiss] [show|list|set|reset]`, `notify (-m -t -p --tag --url -d | --json)`, `sounds [filter]`, `logs [--error]`, `update`, `uninstall`, `version`, `start`.
  - The formula name `jkrumm/tap/ntfy-mac`.
  - The priority mapping table in the README: sound, interruption level and auto-dismiss per priority.

  The token moves to the Keychain on first run, and the plaintext field is removed from the config. Old artifacts get cleaned up: the `com.jkrumm.ntfy-mac` LaunchAgent, the `homebrew.mxcl.ntfy-mac` service, `ntfy-notify.app`, and its Launch Services registrations.
- **The 1.x reference is the TypeScript in `src/` and `tests/`.** Port the edge cases its tests encode before deleting it. `src/` is deleted only in the cutover wave.
- **Known 1.x defects the rewrite must not carry over:**
  - The "updated to X" notice repeats after every restart.
  - The startup replay bypasses the missed-message policy.
  - Messages are lost before the first message arrives, because `since` is still `latest`.
  - Connecting has no timeout, and there is no reconnect on wake.
  - Backoff only resets when a message arrives.
  - Starting offline crash-loops the service.
  - The updater does no checksum.
  - The token is stored in plaintext.
  - URL schemes opened from messages are not restricted.
  - Icons and attachments are fetched without a size limit or same-origin check.
  - `notify` and `doctor` exit 0 on failure.
  - `doctor` changes the install and posts a real notification.
- **Inspiration (read, never copy code):**
  - `NtfyBar`: reconnect state machine, cursor advanced only after the message is stored, `INSERT OR IGNORE` dedup.
  - `Pling`: re-alert until acknowledged, scheme allowlist, same-origin credentials, pause and resume on sleep and wake.
  - `ntfy-macos`: loopback HTTP server that rejects browser requests.
- **Verify library and API facts with `/research`**, never from memory.

## Decisions

| Concern | Decision |
|-|-|
| Layout | SwiftPM package at the repo root: `NtfyCore` library, `ntfy-mac` CLI executable, tests. Thin Xcode app target generated by XcodeGen (`App/project.yml`). |
| Process model | The app (`NtfyMac.app`, LSUIElement) is the only long-lived process: it holds the stream, posts notifications and writes history. The CLI lives at `NtfyMac.app/Contents/MacOS/ntfy-mac`; brew and curl symlink it onto PATH. |
| CLI ↔ app | Reads go directly to the files: config, and the history DB read-only in WAL mode. Mutations write the config and the app watches it (DispatchSource). Things only the app can do (post a notification, ack, reconnect) go over a Unix domain socket, NDJSON request/response, in the app support dir. If the app isn't running, the CLI launches it via LaunchServices and retries. |
| Transport | NDJSON `/<topics>/json` stream through `URLSession.bytes(for:)`, which every native client and ntfy's own docs recommend. Not SSE. |
| Reconnect | A pure state machine with an injectable clock: jittered backoff that resets after a healthy period; 401/403 and redirects are terminal (never send the token to another host); 429 means a long backoff; the watchdog is max(90 s, 2× the observed keepalive gap). Reconnects immediately on `NSWorkspace.didWake` and on an `NWPathMonitor` path change. `ProcessInfo.beginActivity` stops App Nap. |
| Server features | Handle `message_delete` / `message_clear` events and `sequence_id` updates (replace or withdraw delivered notifications). Surface `X-Messages-Truncated`. Respect the 150-topic cap. |
| Persistence | GRDB/SQLite in WAL mode, mode 600. Primary key `(server, topic, id)`, FTS5 for search, per-topic retention, pruning on a timer (not only at launch). |
| Secrets | Keychain, generic password, service `com.jkrumm.ntfy-mac`. |
| Login item | `SMAppService.mainApp`, opt-in during onboarding, can be toggled from the CLI. |
| Bundle IDs | Direct build `com.jkrumm.ntfy-mac`; the App Store build gets its own ID (decided in Wave 7). Notification permission has to be granted again once, coming from the old `com.jkrumm.ntfy-notify` helper. |
| Min OS | macOS 15, Apple Silicon only (1.x is arm64-only as well). |
| Signing | Ad-hoc until the Developer ID arrives. Every signing step goes through one script, so switching to notarized is a config change. |
