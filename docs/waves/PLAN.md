# ntfy-mac 2.0 — native Swift rewrite

**Goal:** one native Swift app replaces the Bun daemon and the Swift helper. It has a menu bar extra, a message history window and native settings. A CLI-first `ntfy-mac` drives the same core: every setting and action works from the CLI, and the UI is a convenience over it. Existing 1.x users upgrade without re-configuring. The direct build (Homebrew + curl) ships first, and a Mac App Store build follows once the Apple Developer membership is active.

**Gate:** `make check`. Wave 1 creates it: `swift format lint --strict`, SwiftLint `--strict`, `swift build` (warnings are errors for our targets), `swift test`, `xcodebuild` of the app scheme, and `bun run validate` while `src/` still exists. `make analyze` (Periphery) joins once the tree is clean. Then `/review` on the wave diff.

## Ground rules (every wave)

- **Compatibility contract.** 2.0 must keep everything below working, or migrate it on first run:
  - Config file `~/.config/ntfy-mac/config.json` (`url`, `token`, `sounds`, `dismiss`, `extraTopics`).
  - Environment variables `NTFY_URL`, `NTFY_TOKEN`, `NTFY_TOPICS`, `NTFY_DEBUG`.
  - State file `~/.local/share/ntfy-mac/state.json`, so the `lastMessageId` cursor carries over.
  - Every 1.x command and flag: `setup [--url --token]`, `doctor [--json]`, `subscribe [topic|reset]`, `unsubscribe`, `config [sounds|dismiss] [show|list|set|reset]`, `notify (-m -t -p --tag --url -d | --json)`, `sounds [filter]`, `logs [--error]`, `update`, `uninstall`, `version`, `start`.
  - The formula name `jkrumm/tap/ntfy-mac`.
  - The priority mapping table in the README: sound, interruption level and auto-dismiss per priority.

  The token moves to the Keychain on first run, and the plaintext field is removed from the config. Old artifacts get cleaned up: the `com.jkrumm.ntfy-mac` LaunchAgent, the `homebrew.mxcl.ntfy-mac` service, `ntfy-notify.app`, and its Launch Services registrations.

- **The 1.x reference is the TypeScript in `src/` and `tests/`.** Port the edge cases its tests encode before deleting it. `src/` is deleted only in the cutover wave.
- **Known 1.x defects the rewrite must not carry over:**
  - The "updated to X" notice repeats after every restart.
  - The startup replay bypasses the missed-message policy.
  - Messages are lost before the first message arrives, because `since` is still `latest`.
  - Connecting has no timeout, and there is no reconnect on wake.
  - Backoff only resets when a message arrives.
  - Starting offline crash-loops the service.
  - The updater does no checksum.
  - The token is stored in plaintext.
  - URL schemes opened from messages are not restricted.
  - Icons and attachments are fetched without a size limit or same-origin check.
  - `notify` and `doctor` exit 0 on failure.
  - `doctor` changes the install and posts a real notification.
- **Inspiration (read, never copy code):**
  - `NtfyBar`: reconnect state machine, cursor advanced only after the message is stored, `INSERT OR IGNORE` dedup.
  - `Pling`: re-alert until acknowledged, scheme allowlist, same-origin credentials, pause and resume on sleep and wake.
  - `ntfy-macos`: loopback HTTP server that rejects browser requests.
- **Verify library and API facts with `/research`**, never from memory.
- **Code quality from day one.** Every tool version is verified with `/research` and pinned (binaries via `scripts/tools.sh` with SHA-256). Swift 6 language mode with complete strict concurrency, warnings as errors for our own targets (not dependencies). Formatting is the toolchain's `swift format` with the checked-in `.swift-format`; `make format` writes, `make check` lints with `--strict`. SwiftLint is pinned with the overlapping formatting rules off and these opt-in rules on: `force_unwrapping`, `force_try`, `implicitly_unwrapped_optional`, `cyclomatic_complexity`, `function_body_length`, `type_body_length`, `file_length`, `nesting`, `fatal_error_message`, `discouraged_optional_boolean`. Tests use Swift Testing (`import Testing`), not XCTest, and go through module interfaces, not internals. lefthook pre-commit runs `swift format lint` on staged Swift files next to commitlint.
- **Human checks never touch the mini's screen.** The owner works on the MacBook and cannot see the mini's notifications. GUI checks that need a human run on the MacBook: build on the mini, install into `~/Applications` there (`make install-macbook`: the MacBook pulls from the mini after one approval dialog), then ask once. Batch them into a single checklist per wave and name the machine in every ask. Anything automatable (screenshots, `log show`, delivered-notification queries) stays automated on the mini.

## Decisions

| Concern            | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layout             | SwiftPM package at the repo root, at most 7 modules plus test fakes, with the dependency direction enforced in `Package.swift`: `NtfyCore` (pure domain and policy, no I/O, depends on nothing; messages, priority/sound/dismiss mapping, missed-message policy, reconnect state machine; the ports `Clock`, `MessageStream`, `SecretStore`, `NotificationPoster`, `HistoryStore`, `ConfigStore` are protocols), `NtfyClient` (HTTP and NDJSON stream), `NtfyStore` (GRDB), `NtfyPlatform` (UserNotifications, Keychain, SMAppService, NSWorkspace wake, NWPathMonitor), `NtfyIPC` (versioned Codable socket protocol), the `ntfy-mac` CLI, and the app (SwiftUI, `@Observable`; thin Xcode target from XcodeGen, `App/project.yml`). `NtfyTesting` holds in-memory fakes for every port. |
| Architecture rules | Actors own mutable state (stream supervisor, delivery queue). No singletons, no global state; one composition root each in the app and the CLI. Typed errors are mapped to exit codes only at the CLI edge. Logging via `os.Logger`, one subsystem with categories.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Process model      | The app (`NtfyMac.app`, LSUIElement) is the only long-lived process: it holds the stream, posts notifications and writes history. The CLI lives at `NtfyMac.app/Contents/MacOS/ntfy-mac`; brew and curl symlink it onto PATH.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| CLI ↔ app          | Reads go directly to the files: config, and the history DB read-only in WAL mode. Mutations write the config and the app watches it (DispatchSource). Things only the app can do (post a notification, ack, reconnect) go over a Unix domain socket, NDJSON request/response, in the app support dir. If the app isn't running, the CLI launches it via LaunchServices and retries.                                                                                                                                                                                                                                                                                                                                                                                                       |
| Transport          | NDJSON `/<topics>/json` stream through `URLSession.bytes(for:)`, which every native client and ntfy's own docs recommend. Not SSE.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Reconnect          | A pure state machine with an injectable clock: jittered backoff that resets after a healthy period; 401/403 and redirects are terminal (never send the token to another host); 429 means a long backoff; the watchdog is max(90 s, 2× the observed keepalive gap). Reconnects immediately on `NSWorkspace.didWake` and on an `NWPathMonitor` path change. `ProcessInfo.beginActivity` stops App Nap.                                                                                                                                                                                                                                                                                                                                                                                      |
| Server features    | Handle `message_delete` / `message_clear` events and `sequence_id` updates (replace or withdraw delivered notifications). Surface `X-Messages-Truncated`. Respect the 150-topic cap.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Persistence        | GRDB/SQLite in WAL mode, mode 600. Primary key `(server, topic, id)`, FTS5 for search, per-topic retention, pruning on a timer (not only at launch).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Secrets            | Keychain, generic password, service `com.jkrumm.ntfy-mac`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Login item         | `SMAppService.mainApp`, opt-in during onboarding, can be toggled from the CLI.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Bundle IDs         | Direct build `com.jkrumm.ntfy-mac`; the App Store build gets its own ID (decided in Wave 7). Notification permission has to be granted again once, coming from the old `com.jkrumm.ntfy-notify` helper.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Min OS             | macOS 15, Apple Silicon only (1.x is arm64-only as well).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Signing            | Ad-hoc until the Developer ID arrives. Every signing step goes through one script, so switching to notarized is a config change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

Backoff 5 s to 5 min with jitter, reset after 60 s of health (not on a message); 401/403, redirect, invalid topic, insecure server halt until `restart()`; 429 waits at least 60 s or `Retry-After`; wake reconnects immediately; offline waits for the path (nothing throws out of the supervisor, so no crash loop); watchdog max(90 s, 2x the largest gap). ## Wave 7 — Developer ID, Sparkle, App Store, one coherent update story <!-- status: pending -->

Not blocked any more (updated 2026-11-06): the paid team exists, Iris signs, notarizes and ships with it, and the mini holds the Developer ID Application identity. The direct channel (Developer ID, Sparkle) is built first; the shared group, cask and App Store items follow as separate Issues once it is proven. Owner goal: Homebrew, direct download and the Mac App Store must coexist without one destroying the other, and updating must never break an install. Decisions from the 2026-11 research (Apple docs, Homebrew docs, Tailscale/Things/1Password practice; macOS 26 prompt behaviour is community-reported only):

- **A Mac App Store build cannot be updated by anything but the App Store (guideline 2.4.5), so "both update the same thing" is not possible. What is possible, and what we build:** one shared state, one owner at a time, and every copy says plainly who updates it.
- **Two bundle IDs, one team:** `com.jkrumm.ntfy-mac` (Developer ID: direct + Homebrew) and `com.jkrumm.ntfy-mac.mas`. Same-ID copies share LaunchServices identity, login item and Keychain defaults in ways Apple does not document; Tailscale separates them, Things shares one and tells users to keep one.
- **Shared state in a Team-ID app group** `TEAMID.com.jkrumm.ntfy-mac` (macOS-style prefix, so macOS 15+ shows no "access data from other apps" prompt): config, history DB, IPC socket (short path, `sun_path` is 104 bytes), instance lock and an owner record. Both builds and the CLI use `containerURL(forSecurityApplicationGroupIdentifier:)`. Never read the other copy's private container. The `~/.config/ntfy-mac/config.json` compatibility contract needs a design decision here (migrate once into the group container and keep reading the old path when no group exists).
- **Ownership:** one copy owns the menu bar and the login item (owner record + lock in the group container); a second launch hands off over the socket and quits; the non-owner unregisters its own login item. `doctor` and the UI show the install channel (App Store receipt in the bundle = App Store; Cellar/Caskroom = Homebrew; else direct) and who updates it. The App Store build has no updater and no direct-download links.
- **Homebrew:** switch from the formula to a **cask** (`app` artifact, `binary` stanza for the CLI, `auto_updates true`) once the build is notarized: casks must pass Gatekeeper, and brew applies quarantine to cask downloads, so an ad-hoc build cannot be a cask. Until then the formula stays. `brew upgrade` skips a self-updating cask whose installed app is the same or newer, so brew and Sparkle do not fight. Migrating the token from formula to cask needs a `tap_migrations`-style plan and a test from a real 2.0 formula install; research it before building.
